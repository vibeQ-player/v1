LESS PASSING THE PHONE. MORE PLAYING THE ROOM.

A little democracy.
A lot of good music.

vibeQ brings requests and voting into one browser-based Spotify player. The host links an account; guests help shape what comes next.

⌕

Find it. Add it.

Search songs and artists with live dropdown results, album art, and keyboard navigation. Add a request directly to the room’s queue.

↑

Votes with balance.

Votes lift favourites while recent requests and plays count toward each guest’s fair share. One person’s long list doesn’t get every turn.

↗

The host stays in control.

Password-protected host controls manage playback, volume, devices, and pending requests. Guests can request and vote without a host password.

FROM A REQUEST TO THE NEXT TRACK

One account.
A room full of taste.

  1. 01

    The host connects Spotify.

    Link an eligible Spotify Premium account and start Spotify on a playback device. The host’s device plays the audio.

  2. 02

    Everyone joins the mix.

    Guests open the player, search, request, and vote. They use the host’s connection rather than signing into separate Spotify accounts.

  3. 03

    The fair queue takes over.

    A background worker sends upcoming requests to Spotify. Closing a guest’s tab doesn’t stop the worker or the host’s Spotify device.

BEFORE YOU PRESS PLAY

A few useful answers.

Do guests need Spotify accounts?

No. Guests search, request, and vote through the host’s Spotify connection. The host needs an eligible Premium account and access to the configured developer app.

Does vibeQ play audio in the browser?

Normally, vibeQ controls a Spotify Connect device such as the desktop app. Browser audio is an optional Spotify Web Playback SDK feature that the host must enable and configure. Closing that browser-player tab stops that playback device.

Can I run vibeQ without a cloud account?

Yes. The local Node.js server uses SQLite and runs its own background workers. You can also adapt it to your preferred hosting provider. A cloud service is optional; Spotify still requires internet access.

How does the queue stay fair?

FPQS (Fair Play Queue System) balances popular requests with each guest’s recent share of the music. Every song has a cost of 1 / (votes + 1). More votes lower that cost; more requests from the same guest accumulate a higher score. The lowest-scoring pending song goes next.

Fi0=Hi,Fik=Fik−1+1vik+1

i is a guest; k is their pending song’s position, ranked by votes first and arrival time second. v is that song’s vote count. H is the sum of costs for that guest’s songs already queued in Spotify and observed plays in the last two hours, including the current requested song while it is in that window. Scores are recalculated as requests, votes, and history change.

Are artwork and trivia included in the demo?

Yes. This demo enables both, with a limit of 20 processed tracks per UTC day. Artwork and sourced trivia appear for the current track when available; new requests can wait until the allowance resets. Cached content is reused. When hosting your own room, configure supported models and your own provider credentials. AI calls can incur charges, and generated trivia can contain mistakes even when sources are linked.

Is this an official Spotify app?

No. vibeQ is an independent, MIT-licensed project. Spotify’s account, developer-app, and playback restrictions apply. A public demo does not automatically grant every host account permission to connect to a development-mode Spotify app. Read Spotify’s quota-mode guidance ↗
